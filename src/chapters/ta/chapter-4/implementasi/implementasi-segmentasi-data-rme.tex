\subsection{Implementasi Segmentasi Data RME}
\label{subsec:implementasi-segmentasi-data-rme}

% Implementasi segmentasi data RME pada subbab ini merupakan realisasi dari \texttt{R-TA-02} melalui komponen \texttt{I-TA-01}. Bagian metadata \textit{on-chain} yang mendukung segmentasi juga terkait dengan \texttt{I-TA-04}.

Segmentasi data RME diimplementasikan dengan memecah satu data RME menjadi beberapa objek data terenkripsi berdasarkan kombinasi \textit{dataset category} dan \textit{function category}. Kombinasi kategori tersebut mengikuti rancangan pada Subbab \ref{subsec:rancangan-segmentasi-data-rme}. Setiap segmen data RME disimpan sebagai satu entri metadata pada penyimpanan \textit{on-chain} dan satu objek data pada penyimpanan \textit{off-chain}.

Segmentasi data RME diimplementasikan pada \textit{crate} \texttt{decmed-rme-segment}. \textit{Crate} ini mendefinisikan \texttt{DatasetCategory} dan \texttt{FunctionCategory} yang digunakan sebagai atribut objek dalam penegakan kebijakan akses terhadap data RME. Rincian modul dan implementasi pada \textit{crate} \texttt{decmed-rme-segment} disajikan pada Lampiran \ref{lampiran:implementasi-crate-decmed-rme-segment}. Implementasi \texttt{DatasetCategory} ditunjukkan pada Kode \ref{lst:implementasi-dataset-category-segmentasi-rme}, implementasi \texttt{FunctionCategory} ditunjukkan pada Kode \ref{lst:implementasi-function-category-segmentasi-rme}.

\begin{lstlisting}[language=Rust, caption=Implementasi \texttt{DatasetCategory} pada \textit{crate} \texttt{decmed-rme-segment}, label={lst:implementasi-dataset-category-segmentasi-rme}]
	pub enum DatasetCategory {

		LABORATORIUM,

\end{lstlisting}

Segmen data ini hanya ada pada \textit{dataset category} \texttt{RAWAT\_INAP}, sedangkan pada \textit{dataset category} \texttt{RAWAT\_JALAN} tidak ada. Selain itu, \textit{function category} \texttt{ADMINISTRATIVE\_GENERAL} ada pada setiap \textit{dataset category}.

\subsubsection{Implementasi Segmentasi Metadata RME pada Penyimpanan \textit{On-Chain}}
\label{subsec:implementasi-segmentasi-metadata-rme-onchain}

Definisi struktur metadata segmentasi ditulis pada \textit{crate} \texttt{decmed-rme-segment}. \textit{Crate} ini mendefinisikan \texttt{RmeSegmentMetadata} yang merupakan representasi metadata segmen sebelum diserialisasi menjadi JSON base64 dan disimpan pada \textit{field} \texttt{metadata} milik \texttt{PatientMedicalMetadata} yang sudah ditunjukkan pada Kode \ref{lst:decmed-patient-medical-metadata}. Implementasi struktur \texttt{RmeSegmentMetadata} terdapat pada Kode \ref{lst:implementasi-segmentasi-metadata-rme}.
Struktur tersebut sesuai dengan rancangan skema metadata segmen RME pada Lampiran Tabel \ref{tab:onchain-schema}.

\begin{lstlisting}[language=Rust, caption=Implementasi struktur \texttt{RmeSegmentMetadata} pada \textit{crate} \texttt{decmed-rme-segment}, label={lst:implementasi-segmentasi-metadata-rme}]
pub struct RmeSegmentMetadata {
	pub segment_id: String,
	pub related_rme_id: String,
	pub patient_address: String,
	pub author_address: String,
	pub hospital_cid: String,
	pub dataset_category: DatasetCategory,
	pub function_category: FunctionCategory,
	pub ipfs_cid: String,
	pub integrity_hash: String,
	pub capsule: String,
	pub enc_key_and_nonce: String,
	pub created_at: String,
}
\end{lstlisting}

Sebelum metadata segmen disimpan pada IOTA, struktur metadata divalidasi terlebih dahulu. Validasi tersebut mencakup pemeriksaan setiap \textit{field} wajib terisi, validitas kombinasi \texttt{dataset\_category} dan \texttt{function\_category}, serta kesesuaian \texttt{integrity\_hash} terhadap data terenkripsi. \texttt{dataset\_category} dan \texttt{function\_category} memiliki nilai sesuai dengan Kode \ref{lst:implementasi-dataset-category-segmentasi-rme} dan \ref{lst:implementasi-function-category-segmentasi-rme}. \texttt{patient\_address} dan \texttt{author\_address} memuat \textit{address wallet} dari pasien dan aktor yang menulis isi segmen. \texttt{hospital\_cid} merupakan \textit{identifier} fasyankes, menunjukkan bahwa segmen data tersebut dihasilkan oleh tenaga medis dari fasyankes tersebut. \texttt{ipfs\_cid} merupakan \textit{pointer} ke data segmen terenkripsi yang disimpan pada penyimpanan \textit{off-chain}. \texttt{integrity\_hash} merupakan hash SHA-256 dari data segmen terenkripsi yang digunakan untuk memverifikasi integritas data. \texttt{capsule} merupakan kapsul PRE yang diperlukan untuk proses \textit{re-encryption}. \texttt{enc\_key\_and\_nonce} merupakan kunci simetris dan \textit{nonce} yang sudah terenkripsi untuk membuka segmen data. \texttt{created\_at} memuat informasi tanggal dan waktu ketika segmen tercatat dengan format \texttt{YYYY-MM-DD HH:MM:SS} serta informasi \textit{timezone}.

\subsubsection{Implementasi Segmentasi Data RME pada Penyimpanan \textit{Off-Chain}}
\label{subsec:implementasi-segmentasi-data-rme-offchain}

Definisi struktur segmentasi data penyimpanan \textit{off-chain} didefinisikan pada \textit{crate} \texttt{decmed-rme-segment}. \textit{Crate} ini mendefinisikan \texttt{RmeSegmentData}, struktur data segmen RME yang disimpan pada penyimpanan \textit{off-chain}. Implementasi struktur \texttt{RmeSegmentData} terdapat pada Kode \ref{lst:implementasi-segmentasi-data-rme}. Struktur tersebut sesuai dengan rancangan skema data segmen RME pada Lampiran Tabel \ref{tab:offchain-schema}.

\begin{lstlisting}[language=Rust, caption=Implementasi struktur \texttt{RmeSegmentData} pada \textit{crate} \texttt{decmed-rme-segment}, label={lst:implementasi-segmentasi-data-rme}]
pub struct RmeSegmentData {
    pub segment_id: String,
    pub related_rme_id: String,
    pub dataset_category: DatasetCategory,
    pub function_category: FunctionCategory,
    pub patient_address: String,
    pub service_date: String,
    pub author_address: String,
    pub payload: Value,
    pub payload_hash: String,
}
\end{lstlisting}

\texttt{segment\_id} merupakan ID unik untuk satu segmen data RME. \texttt{dataset\_category} dan \texttt{function\_category} digunakan sebagai atribut objek untuk penegakan kebijakan akses terhadap data RME. Atribut tersebut memiliki nilai sesuai dengan Kode \ref{lst:implementasi-dataset-category-segmentasi-rme} dan \ref{lst:implementasi-function-category-segmentasi-rme}. \texttt{patient\_address} dan \texttt{author\_address} memuat \textit{address wallet} dari pasien dan aktor yang menulis isi segmen. \texttt{service\_date} merupakan tanggal dan waktu ketika segmen tercatat dengan format \texttt{YYYY-MM-DD HH:MM:SS} beserta informasi \textit{timezone}. \texttt{payload} berisi konten utama segmen dengan tipe data \texttt{Value}. Pada implementasi ini, \texttt{payload} berisi data dalam bentuk \texttt{text}. \texttt{payload\_hash} merupakan hash integritas dari konten \texttt{payload}.

% \texttt{payload\_hash} dihitung dari isi \texttt{payload} sebelum enkripsi, sedangkan \texttt{integrity\_hash} dihitung dari data segmen terenkripsi yang disimpan di IPFS. Dengan demikian, \texttt{payload\_hash} digunakan untuk integritas isi segmen sebelum enkripsi, sedangkan \texttt{integrity\_hash} digunakan untuk memverifikasi kesesuaian \textit{ciphertext} IPFS dengan metadata pada IOTA.

Pada saat data RME disimpan, \textit{Hospital Client} membentuk objek untuk setiap segmen. Setiap segmen berisi data klinis atau administratif sesuai kategorinya, kemudian dienkripsi sebelum diunggah ke IPFS. Hasil unggahan IPFS berupa CID disimpan bersama metadata segmen pada IOTA sebagai \texttt{ipfs\_cid}. Metadata tersebut disimpan dalam bentuk serialisasi JSON dan dikodekan dalam base64 pada \textit{field} \texttt{metadata} milik \texttt{PatientMedicalMetadata}. Keputusan ini menjaga kompatibilitas dengan struktur penyimpanan DecMed yang masih berbentuk daftar metadata \textit{flat}, tetapi tetap memungkinkan \textit{Server} PRE membaca kategori segmentasi dari isi metadata.

% Pada implementasi ini, \texttt{RmeSegmentData} digunakan sebagai representasi segmen sebelum enkripsi pada sisi \textit{client}. Setelah \texttt{payload} dienkripsi, segmen direpresentasikan sebagai \texttt{ClientEncryptedRmeSegment} yang masih memuat \textit{ciphertext}. Struktur tersebut kemudian dikonversi menjadi \texttt{RmeSegmentMetadata} dengan menghilangkan isi \textit{ciphertext} dan mempertahankan metadata yang diperlukan untuk pencarian, validasi integritas, dan proses PRE. Metadata ini kemudian diserialisasi sebagai JSON base64 sebelum disimpan pada field \texttt{metadata} di IOTA.

% Implementasi ini membuat proses otorisasi dapat dilakukan pada tingkat segmen. Sebagai contoh, token Macaroon yang hanya memuat izin baca untuk \texttt{RAWAT\_JALAN}, fungsi \texttt{PEMERIKSAAN\_PENUNJANG}, dan \texttt{related\_rme\_id} tertentu hanya dapat digunakan untuk meminta segmen yang berada pada episode dan kategori tersebut. Segmen lainnya seperti \texttt{DIAGNOSIS}, \texttt{TERAPI}, atau \texttt{PERESEPAN} tidak akan dikirimkan ke \textit{client} oleh \textit{Server} PRE karena metadata segmennya tidak termasuk dalam cakupan efektif Macaroon.

% Dengan pendekatan ini, IOTA berperan sebagai penyimpanan metadata dan sumber rujukan status segmen, sedangkan penegakan aturan akses berdasarkan kategori dilakukan oleh \textit{Server} PRE pada saat permintaan baca atau tulis diproses.

% Segmentasi juga digunakan pada proses pembaruan data. Ketika aktor menulis data baru, \textit{Hospital Client} hanya membuat atau memperbarui segmen yang berada dalam cakupan izin tulis aktor tersebut. Dengan demikian, petugas laboratorium dapat menambahkan hasil pemeriksaan ke segmen data laboratorium tanpa memperoleh akses tulis terhadap segmen diagnosis atau terapi. Pembaruan segmen direpresentasikan dengan perubahan metadata, misalnya perubahan \texttt{ipfs\_cid} dan pengisian \texttt{updated\_at}, tanpa memberikan hak tulis terhadap segmen lain di luar cakupan token.
