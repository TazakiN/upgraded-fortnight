\subsubsection{Autentikasi Token Macaroon}
\label{subsec:autentikasi-token-macaroon}

\textit{Middleware} PRE membaca token dari \textit{header} \texttt{Authorization} skema \texttt{Bearer}, mendeserialisasi token, mem-\textit{parsing} \textit{caveats} DecMed, dan memverifikasi \textit{chained-HMAC} dengan \texttt{RootKey}. Token yang gagal deserialisasi, bukan token DecMed, atau HMAC-nya tidak valid ditolak.

Dari \textit{caveats} yang valid, PRE membentuk \texttt{EffectiveCapability} (Kode \ref{lst:definisi-effective-capability}): irisan untuk \textit{caveat} bertipe himpunan, dan nilai paling awal untuk \texttt{expires\_before}. \texttt{DelegationChain} (Kode \ref{lst:definisi-delegation-chain}) menentukan subjek berwenang melalui \texttt{subjects()} (\texttt{root\_subject} plus seluruh \texttt{delegated\_to}); keanggotaan diperiksa lewat \texttt{contains\_subject()}, dan setiap langkah delegasi harus tersambung konsisten.
% Apabila token merupakan hasil delegasi antaraktor, \textit{middleware} juga memverifikasi bukti delegasi melalui \textit{header} \texttt{x-decmed-delegation-signature}. 

\begin{lstlisting}[language=Rust, caption={Definisi \texttt{EffectiveCapability}}, label={lst:definisi-effective-capability}]
pub struct EffectiveCapability {
    pub read_datasets: HashSet<DatasetCategory>,
    pub write_datasets: HashSet<DatasetCategory>,
    pub read_functions: HashSet<FunctionCategory>,
    pub write_functions: HashSet<FunctionCategory>,
    pub expires_before: Option<DateTime<Utc>>,
    pub root_max_delegation_depth: Option<u32>,
    pub remaining_max_delegation_depth: Option<u32>,
    pub patient_address: Option<String>,
    pub related_rme_id: Option<String>,
    pub hospital_cid: Option<String>,
}
\end{lstlisting}

\begin{lstlisting}[language=Rust, caption={Definisi \texttt{DelegationStep} dan \texttt{DelegationChain}}, label={lst:definisi-delegation-chain}]
pub struct DelegationStep {
    pub delegated_by: String,
    pub delegated_to: String,
}

pub struct DelegationChain {
    pub root_subject: String,
    pub steps: Vec<DelegationStep>,
}
\end{lstlisting}

Setelah kedua struktur terbentuk, PRE menolak token jika \texttt{expires\_before} sudah lewat atau jumlah \texttt{steps} pada rantai melebihi \texttt{max\_delegation\_depth}.

\subsubsection{Pemeriksaan Status Revokasi Token}
\label{subsec:pemeriksaan-status-revokasi-token}

Pemeriksaan status revokasi pada jalur akses merealisasikan predikat $\neg\operatorname{Revoked}(\tau)$. \textit{Middleware} PRE membandingkan \textit{hash} token yang digunakan serta \textit{hash} pada \textit{caveat} \texttt{parent\_token\_hash} terhadap kunci Redis \texttt{revoked:token:<token\_hash>}. Jika salah satu cocok, permintaan ditolak dengan \texttt{401 UNAUTHORIZED}. Alur pencabutan \textit{on-chain}, penanda Redis, dan sifat berantai revokasi diuraikan pada Subbab \ref{subsubsec:revokasi-token-macaroons}.

\subsubsection{Verifikasi Bukti Kepemilikan \textit{Wallet}}
\label{subsec:verifikasi-bukti-kepemilikan-wallet}

Bukti dikirim lewat \textit{header} \texttt{x-decmed-wallet-signature} dan \texttt{x-decmed-wallet-timestamp}, ditandatangani atas \texttt{WalletProofContext} (Kode \ref{lst:struktur-walletproofcontext}). PRE mencocokkan tanda tangan terhadap \texttt{DelegationChain::subjects()}; jika cocok, alamat tersebut menjadi identitas pemohon untuk pemeriksaan lanjutan. Timestamp diterima dalam rentang 5 menit. \textit{Smart contract} IOTA tidak memverifikasi \texttt{WalletProofContext}; kontrak hanya menyediakan atribut kelembagaan setelah alamat terbukti di PRE.

\begin{lstlisting}[language=Rust, caption={Struktur \texttt{WalletProofContext} sebagai konteks verifikasi \textit{wallet signature}}, label={lst:struktur-walletproofcontext}]
pub struct WalletProofContext {
	pub token_id: String,       // ID Macaroon
	pub patient_address: String,// Alamat pasien
	pub related_rme_id: String, // ID episode RME
	pub operation: AccessMode,  // Read / Update
	pub segment_id: String,     // ID segmen yang diakses
	pub dataset_category: DatasetCategory,
	pub function_category: FunctionCategory,
	pub timestamp: String,		// YYYY-MM-DD HH:MM:SS
}
\end{lstlisting}

Pada jalur baca, jika tanda tangan belum disertakan, PRE mengembalikan \texttt{401 UNAUTHORIZED} berisi \texttt{proof\_context} agar \textit{client} menandatangani dan mengirim ulang permintaan.

\subsubsection{Verifikasi \textit{Role} dan \textit{Subrole} melalui \textit{Move Smart Contract}}
\label{subsec:validasi-role-subrole-move-smart-contract}

Setelah \textit{wallet proof} berhasil, PRE memanggil \texttt{get\_hospital\_personnel\_auth\_info} untuk memperoleh \textit{role} dan \textit{subrole} on-chain. Pemetaan hak tulis mengikuti Tabel \ref{tab:pemetaan-hak-akses-update-subrole} pada Subbab \ref{subsubsec:verifikasi-role-tenaga-medis-untuk-akses-dataset}.

\subsubsection{Verifikasi Konteks Segmen}
\label{subsec:verifikasi-konteks-segmen}

Pada \textit{handler} baca, metadata segmen diambil dari IOTA lalu didekode dari JSON base64. Pada tulis, metadata \textit{preview} dibentuk dari \textit{payload}. Konteks digabung sebagai \texttt{SegmentAccessContext} (\texttt{segment\_id}, \texttt{patient\_address}, \texttt{related\_rme\_id}, \texttt{dataset\_category}, \texttt{function\_category}) dan dibandingkan dengan \texttt{EffectiveCapability}: baca terhadap \texttt{read\_dataset\_in}/\texttt{read\_function\_in}; tulis terhadap \texttt{write\_dataset\_in}/\texttt{write\_function\_in} beserta kesesuaian \texttt{related\_rme\_id} dan \texttt{hospital\_cid}. Pemeriksaan \textit{role}/\textit{subrole} untuk tulis mengacu pada Tabel \ref{tab:pemetaan-hak-akses-update-subrole}; \texttt{AdministrativePersonnel} hanya dapat menulis \texttt{ADMINISTRATIVE\_GENERAL}.

\subsubsection{Eksekusi Operasi \textit{Re-encryption}, IPFS, dan IOTA}
\label{subsec:eksekusi-operasi-re-encryption-ipfs-iota}

Setelah otorisasi lolos, PRE menghubungkan \textit{ciphertext} di IPFS, metadata di IOTA, material \texttt{k\_frag}/\texttt{c\_frag} di Redis, dan respons ke \textit{client}. Dasar PRE dan analisis perannya dijelaskan pada Subbab \ref{subsec:umbral-pre} dan \ref{subsec:analisis-penegakan-otoritas-pre}. Alur baseline DecMed diilustrasikan pada Gambar~\ref{fig:proses-enkripsi-penyimpanan-rme}--\ref{fig:proses-reenkripsi-dekripsi-hospital-client}; skema metadata pada Lampiran \ref{lampiran:skema-penyimpanan-rme}. Respons tulis berisi ringkasan metadata segmen. PRE hanya mengubah akses terhadap \texttt{capsule}; \textit{plaintext} dan kunci AES muncul di sisi \textit{client} setelah dekripsi valid.
