\subsection{Analisis Pemilihan Token Otorisasi}
\label{subsec:analisis-pemilihan-token-otorisasi}

Berdasarkan masalah yang telah diidentifikasi pada Subbab \ref{subsec:identifikasi-masalah},
mekanisme otorisasi pada DecMed perlu mendukung kontrol akses granular dan memiliki mekanisme atuneasi. Selain itu, pada Subbab \ref{subsec:analisis-delegasi-atenuasi-offline} dibahas bahwa mekanisme delegasi antaraktor perlu mendukung atenuasi \textit{offline}.
Oleh karena itu, diperlukan analisis perbandingan terhadap beberapa pendekatan token otorisasi untuk menentukan teknologi token otorisasi yang paling sesuai dengan kebutuhan sistem.

Alternatif token otorisasi yang dibandingkan pada analisis ini adalah JWT, PASETO, Macaroons, dan Biscuit. JWT dipilih sebagai pembanding karena merupakan bentuk token yang digunakan pada rancangan DecMed awal dan umum digunakan untuk merepresentasikan klaim otorisasi. PASETO dipilih karena memiliki tujuan penggunaan yang serupa dengan JWT, tetapi dengan kriptografi yang \textit{opinionated}. Macaroons dianalisis sebagai kandidat utama karena menyediakan mekanisme \textit{caveat} yang memungkinkan atenuasi \textit{offline}. Biscuit dianalisis sebagai pembanding karena mendukung verifikasi terdesentralisasi dan atenuasi \textit{offline}, tetapi menggunakan pendekatan yang lebih ekspresif melalui aturan berbasis \textit{logic language}.

Kriteria evaluasi antar token diturunkan dari kebutuhan sebagai berikut:
\begin{enumerate}
	\item \textbf{Representasi batasan akses granular}

	      Menilai apakah token dapat membawa batasan akses yang dibutuhkan agar token benar-benar dapat mengekspresikan pembatasan akses sesuai kebutuhan.
	\item \textbf{Atenuasi \textit{offline}}

	      Menilai apakah pemegang token dapat menambahkan batasan baru tanpa harus melibatkan pasien dan menerbitkan token baru. Sesuai dengan solusi dari Subbab \ref{subsec:analisis-delegasi-atenuasi-offline}.
	\item \textbf{Jaminan token turunan tidak memperluas hak akses}

	      Menganalisis jenis kunci kriptografi yang digunakan dan seberapa kuat sistem delegasi token mencegah token turunan digunakan untuk mengakses lebih banyak atau lebih luas daripada token induknya.
	\item \textbf{Model verifikasi dan pengelolaan kunci}

	      Mengkaji bagaimana masing-masing token diverifikasi dan bagaimana pengelolaan kuncinya.
	\item \textbf{Kesesuaian ekspresivitas dengan aturan akses DecMed}

	      DecMed membutuhkan token yang dapat mengekspresikan batasan akses secara langsung sebagai atribut pada token itu sendiri.
	\item \textbf{Kompleksitas integrasi ke PRE}

	      membahas tingkat kesulitan integrasi ke dalam sistem PRE sebagai penegak otoritas akses.
\end{enumerate}

JWT dan PASETO dapat digunakan untuk membawa informasi otorisasi dalam bentuk klaim, seperti identitas subjek, cakupan akses, dan waktu kedaluwarsa. Namun, keduanya tidak menyediakan mekanisme bawaan untuk menambahkan batasan baru pada token yang sudah diterbitkan. Akibatnya, delegasi hak akses yang lebih sempit tetap membutuhkan penerbitan token baru oleh pihak penerbit atau mekanisme tambahan di sisi \textit{server}. Karakteristik tersebut kurang sesuai dengan kebutuhan delegasi \textit{offline} pada Tugas Akhir ini.

Macaroons dan Biscuit lebih dekat dengan kebutuhan karena keduanya mendukung atenuasi \textit{offline}. Perbedaan utama keduanya terletak pada model pembatasan dan model verifikasi. Macaroons menggunakan \textit{caveats} untuk menambahkan batasan pada token, sedangkan Biscuit menggunakan blok berisi \textit{fact}, \textit{rule}, dan \textit{check}. Model Biscuit memberikan ekspresivitas yang lebih tinggi, tetapi kebutuhan pembatasan akses pada DecMed masih dapat direpresentasikan melalui klaim pada token, seperti identitas pasien, identitas aktor, cakupan data, aksi, dan masa berlaku. Pembatasan tersebut hanya memanfaatkan \textit{fact} saja, karena pemeriksaan otoritas dari klaim pada token sudah cukup ditangani oleh \textit{server} PRE.Oleh karena itu, penggunaan Biscuit dinilai menambah kompleksitas integrasi yang tidak diperlukan untuk ruang lingkup Tugas Akhir ini.

Dari sisi model verifikasi, Macaroons lebih sesuai dengan rancangan DecMed karena proses verifikasi token tetap dipusatkan pada \textit{Server} PRE sebagai titik penegakan otorisasi. Dengan model tersebut, kunci verifikasi tidak perlu disebarkan ke banyak layanan. Biscuit lebih sesuai untuk arsitektur yang membutuhkan verifikasi token oleh banyak komponen berbeda menggunakan kunci publik. Pada rancangan DecMed, kebutuhan tersebut tidak menjadi fokus karena seluruh akses data RME tetap melewati PRE.

Berdasarkan perbandingan tersebut, Macaroons dipilih sebagai mekanisme token otorisasi pada DecMed karena memberikan keseimbangan antara representasi batasan akses granular, dukungan delegasi terbatas melalui atenuasi \textit{offline}, dan kompleksitas integrasi yang sesuai dengan ruang lingkup Tugas Akhir. Melalui mekanisme \textit{caveats}, token dapat membawa batasan akses dan pemegang token dapat menambahkan batasan baru secara lokal untuk mempersempit hak akses sebelum token didelegasikan kepada aktor lain.
