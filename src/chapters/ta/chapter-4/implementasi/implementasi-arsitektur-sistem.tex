\subsection{Implementasi Arsitektur Sistem}
\label{subsec:implementasi-arsitektur-sistem}

Implementasi arsitektur sistem mengikuti rancangan pada Subbab \ref{subsec:rancangan-arsitektur-solusi}. Komponen dasar DecMed dipertahankan, yaitu IOTA untuk metadata \textit{on-chain}, IPFS untuk penyimpanan segmen data yang terenkripsi, dan \textit{Server} PRE sebagai penegak otoritas dan distribusi akses terhadap data terenkripsi. Perubahan utama pada implementasi ini berada pada lapisan otorisasi dan struktur data, yaitu data RME dibuat tersegmentasi, token akses diganti dengan Macaroons, dan \textit{Hospital Client} mendukung pembuatan token turunan melalui atenuasi lokal.

% \textit{Patient Client} digunakan untuk memberikan akses awal, \textit{Hospital Client} digunakan untuk membaca atau menulis segmen RME serta membuat token turunan, sedangkan \textit{Ministry Client} tetap digunakan untuk kebutuhan registrasi rumah sakit. Seluruh permintaan akses terhadap RME melewati \textit{Server} PRE sebagai titik penegakan kebijakan akses.

% Alur implementasi akses data diawali dari \textit{client} yang mengirimkan permintaan akses beserta token Macaroon dan bukti kepemilikan \textit{wallet}. \textit{Server} PRE kemudian membaca metadata segmen RME dari IOTA untuk memperoleh informasi kategori data, lokasi CID pada IPFS, dan data kriptografis yang diperlukan. Apabila seluruh pemeriksaan otorisasi berhasil, \textit{Server} PRE mengambil segmen terenkripsi dari IPFS, menjalankan proses \textit{re-encryption}, lalu mengembalikan hasil yang dapat dibuka oleh pemohon akses.

% Dengan penempatan tersebut, \textit{Server} PRE berperan sebagai titik penegakan akses yang menghubungkan tiga hal, yaitu token Macaroon sebagai bukti kapabilitas, metadata IOTA sebagai sumber kebenaran kategori segmen, dan IPFS sebagai penyimpanan isi RME terenkripsi. Redis digunakan sebagai komponen pendukung untuk \textit{nonce}, kunci akses PRE, dan pencabutan akses. Arsitektur ini memungkinkan kontrol akses granular diterapkan tanpa mengubah prinsip dasar DecMed yang memisahkan metadata \textit{on-chain} dan data terenkripsi \textit{off-chain}.

Selain perubahan pada alur otorisasi, implementasi juga memperbaiki pola pengorganisasian kode. Pada DecMed awal, beberapa bagian yang memiliki fungsi serupa ditulis berulang pada beberapa komponen. Pola tersebut membuat perubahan kode menjadi lebih sulit di-\textit{maintain} karena perubahan pada satu bagian perlu direplikasi pada komponen lain. Pada implementasi ini, bagian yang digunakan bersama dipisahkan menjadi \textit{crate} Rust agar dapat digunakan ulang oleh beberapa komponen.

Dua \textit{crate} utama yang dibuat adalah \texttt{decmed-rme-segment} dan \texttt{decmed-macaroon-auth}.
\texttt{decmed-rme-segment} berisi definisi kategori segmen RME, kategori fungsi klinis, serta struktur data metadata segmen RME. Sementara itu, \texttt{decmed-macaroon-auth} berisi implementasi token otorisasi berbasis Macaroons, termasuk pembuatan token, penambahan \textit{caveat}, atenuasi token, dan proses verifikasi. \textit{crate} ini memiliki dependensi utama yaitu \textit{crate} \texttt{macaroon-decmed} yang merupakan \textit{crate open source} dari implementasi \texttt{macaroons} pada Rust yang diperbaharui \textit{dependencynya}. \texttt{decmed-rme-segment} digunakan oleh \textit{Patient Client}, \textit{Hospital Client}, dan \textit{Server} PRE, sedangkan \texttt{decmed-macaroon-auth} digunakan oleh \textit{Hospital Client} dan \textit{Server} PRE. \textit{Ministry Client} tidak memiliki dependensi langsung terhadap kedua \textit{crate} tersebut karena perannya tetap terbatas pada kebutuhan registrasi dan aktivasi rumah sakit. Hubungan antar komponen implementasi dan dependensi \textit{crate} bersama ditunjukkan pada \textit{package diagram} pada Gambar \ref{fig:package-diagram-implementasi} dengan legenda dari \textit{package diagram} tersebut dapat dilihat pada Lampiran \ref{lampiran:legenda-package-diagram}.

Dengan pemisahan tersebut, implementasi segmentasi data dan otorisasi tidak tersebar sebagai kode duplikatif pada setiap komponen. \textit{Patient Client}, \textit{Hospital Client}, dan \textit{Server} PRE menggunakan \texttt{decmed-rme-segment} untuk menjaga konsistensi representasi kategori dataset, kategori fungsi, dan metadata segmen RME. Sementara itu, \textit{Hospital Client} dan \textit{Server} PRE menggunakan \texttt{decmed-macaroon-auth} untuk kebutuhan otorisasi berbasis Macaroons. Pada \textit{Hospital Client}, \textit{crate} tersebut digunakan untuk membaca kapabilitas token dan membuat token turunan melalui atenuasi lokal. Pada \textit{Server} PRE, \textit{crate} tersebut digunakan untuk menerbitkan token awal, memverifikasi \textit{caveat}, memeriksa cakupan akses terhadap segmen RME, dan mendukung mekanisme pencabutan akses.
