\subsubsection{Delegasi Akses dari Pasien kepada Petugas Rekam Medis}
\label{subsubsec:delegasi-akses-dari-pasien-kepada-petugas-rekam-medis}

Implementasi mengikuti rancangan pada Subbab \ref{subsubsec:penerbitan-token-awal-oleh-pasien-kepada-petugas-rekam-medis}. Detail teknis yang diwujudkan sebagai berikut.

QR code \texttt{AdministrativePersonnel} memuat \textit{string} berformat \verb|{hospitalCid}@{personnelIota}@{personnelPrePK}|, yaitu \texttt{hospital\_cid}, alamat IOTA petugas, dan PRE \textit{public key} petugas (base64). Setelah \textit{scan}, \textit{Patient Client} memanggil \textit{smart contract} \verb|get_hospital_personnel_info| untuk memuat identitas publik petugas. Pasien memilih \texttt{RAWAT\_JALAN} atau \texttt{RAWAT\_INAP} serta mode akses \texttt{read}, \texttt{update}, atau \texttt{read\_update}. Batas waktu bawaan adalah 1 hari untuk \texttt{RAWAT\_JALAN} dan 3 hari untuk \texttt{RAWAT\_INAP}; nilai \texttt{expires\_before} khusus tetap didukung.

\textit{Patient Client} meminta \textit{nonce} melalui \textit{endpoint} \texttt{/nonce}. Sebelum diterbitkan, PRE memeriksa registrasi pasien lewat \verb|is_patient_registered|. \textit{Nonce} ditandatangani dengan kunci IOTA pasien. Bersamaan itu, \textit{Patient Client} membuat \texttt{data\_pre\_secret\_key\_seed}, menurunkan \texttt{data\_pre\_public\_key}, mengenkripsi \textit{seed} dengan \texttt{personnel\_pre\_public\_key}, dan membentuk \texttt{k\_frag} dari PRE \textit{secret key} pasien menuju \texttt{data\_pre\_public\_key}. Material PRE disimpan di Redis dengan TTL mengikuti waktu kedaluwarsa token.

Permintaan penerbitan dikirim ke \textit{endpoint} \texttt{/keys} dengan \textit{payload}: alamat IOTA pasien dan petugas, \texttt{hospital\_cid}, \texttt{encounter\_dataset}, mode akses, \textit{signature} pasien, \texttt{k\_frag}, \texttt{data\_pre\_public\_key}, \texttt{enc\_data\_pre\_secret\_key\_seed}, \texttt{data\_pre\_secret\_key\_seed\_capsule}, \texttt{patient\_pre\_public\_key}, dan \texttt{signer\_pre\_public\_key}. PRE memverifikasi \textit{signature} terhadap \textit{nonce} dan memastikan \textit{role} penerima adalah \texttt{AdministrativePersonnel}. Jika valid, PRE membentuk \texttt{MacaroonKey} dari \texttt{RootKey} dan menerbitkan token sesuai mode. Susunan \textit{caveat} token \texttt{Read} dan \texttt{Update} mengikuti Tabel \ref{tab:implementasi-caveats-macaroons} dan Subbab \ref{subsubsec:penerbitan-awal-token-macaroons}. Pada token \texttt{Update}, \texttt{write\_dataset\_in} dibatasi pada \texttt{encounter\_dataset} yang dipilih, ditambah \texttt{LABORATORIUM} dan \texttt{APOTEK}; \texttt{write\_function\_in} diturunkan dari kategori fungsi dalam cakupan tersebut.

\texttt{related\_rme\_id} hanya dibuat jika akses mencakup \texttt{Update}, dengan format \verb|RME-{sequence_6_digit}| (misalnya \verb|RME-000001|); \textit{sequence} disimpan di Redis. Material akses PRE disimpan dengan kunci Redis \verb|{personnel_iota_address}@{patient_iota_address}|. Respons ke \textit{Patient Client} memuat \texttt{access\_token\_read}, \texttt{access\_token\_update}, \textit{hash} masing-masing token, serta \texttt{related\_rme\_id} bila ada. Token dan metadata akses dienkripsi dengan \texttt{personnel\_pre\_public\_key}, lalu dicatat ke IOTA melalui \texttt{create\_access}.

\subsubsection{Delegasi Akses Antartenaga Kesehatan}
\label{subsubsec:delegasi-akses-antar-tenaga-kesehatan}

Implementasi mengikuti rancangan pada Subbab \ref{subsec:delegasi-dari-petugas-rekam-medis-kepada-perawat-dan-dokter} dan \ref{subsec:delegasi-dari-dokter-kepada-laboratorium-dan-apoteker}, dengan pemetaan \textit{subrole} pada Tabel \ref{tab:pemetaan-hak-akses-update-subrole}.

\textit{Delegator} memilih \textit{delegatee} melalui \texttt{get\_delegatee\_candidates} (alamat IOTA dan PRE \textit{public key} penerima). \textit{Hospital Client} memuat material kriptografis \textit{delegator}, mendekripsi \texttt{data\_pre\_secret\_key\_seed}, lalu mengenkripsi ulang \textit{seed} dengan PRE \textit{public key} \textit{delegatee}. Permintaan atenuasi ke PRE memuat token induk, cakupan yang diminta, waktu kedaluwarsa, alamat \textit{delegator}/\textit{delegatee}/pasien, tanda tangan delegasi induk bila token induk hasil delegasi, serta \texttt{delegation\_request\_signature} (tanda tangan IOTA atas \texttt{DelegationRequestProofContext}).

PRE memverifikasi token induk (\textit{chained-HMAC} dan status revokasi), memvalidasi bahwa cakupan turunan adalah subset dari \texttt{EffectiveCapability} induk (Kode \ref{lst:definisi-effective-capability}), lalu memeriksa metadata akses di IOTA melalui \texttt{get\_delegation\_access\_snapshot} (kedaluwarsa hak \textit{delegator}, kesamaan fasyankes, kedalaman delegasi, dan absennya delegasi aktif untuk \textit{subrole} yang sama). Jika lolos, atenuasi dilakukan lewat \texttt{attenuate\_macaroon} pada \textit{crate} \texttt{decmed-macaroon-auth}. Contoh \textit{caveat} turunan sesuai \textit{preset} ada pada Lampiran \ref{lampiran:contoh-caveat-macaroon}.

Setelah token turunan diterima, \textit{client} membentuk bukti dengan \texttt{DelegationProofContext} (Kode \ref{lst:definisi-delegation-proof-context}). Nilai \texttt{scope\_fingerprint} adalah \textit{hash} berpola \verb!r:{ds_read}|w:{ds_write}|rf:{fn_read}|wf:{fn_write}!. Konteks tersebut diserialisasi dan ditandatangani dengan kunci IOTA \textit{delegator}.

\begin{lstlisting}[language=Rust, caption={Definisi \texttt{DelegationProofContext}}, label={lst:definisi-delegation-proof-context}]
pub struct DelegationProofContext {
    pub token_hash: String,
    pub delegated_by: String,
    pub delegated_to: String,
    pub related_rme_id: String,
    pub expires_before: String,
    pub scope_fingerprint: String,
}
\end{lstlisting}

Metadata delegasi (token turunan, \textit{hash}, tanda tangan, metadata akses, dan \textit{seed} yang dienkripsi ulang) dienkripsi dengan PRE \textit{public key} \textit{delegatee}, lalu dicatat melalui \texttt{create\_delegated\_access}. Fungsi tersebut memvalidasi status \textit{delegatee}, kesamaan fasyankes, dan validitas akses \textit{delegator}, kemudian menulis entri akses serta audit (alamat \textit{delegator}, \textit{root subject}, \textit{delegatee}, jenis akses, \texttt{related\_rme\_id}, kedalaman, \textit{hash} token turunan/induk, dan kedaluwarsa).

Pada delegasi pertama dari \texttt{AdministrativePersonnel} ke \texttt{MedicalPersonnel}, \textit{function category} \texttt{ADMINISTRATIVE\_GENERAL} ditambahkan pada setiap \textit{dataset category} yang didelegasikan, sesuai Lampiran \ref{lampiran:metadata-rme}. Saat akses digunakan, verifikasi mengikuti Subbab \ref{subsec:implementasi-penegakan-otoritas-pre}; material PRE di Redis dicari berdasarkan aktor pemohon, aktor pada rantai delegasi, hingga \texttt{root\_subject}.
